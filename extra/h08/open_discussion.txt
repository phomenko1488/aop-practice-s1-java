1. Як знайти найбільше число в масиві?
Алгоритм:
Ініціалізувати змінну максимуму першим значенням масиву: int max = nums[0];. Помилкою є ініціалізація нулем (int max = 0), оскільки якщо всі елементи масиву від'ємні, результат буде некоректним.
Запустити лінійний цикл від другого елемента до кінця масиву (for (int i = 1; i < nums.length; i++)).
Якщо nums[i] > max, оновити: max = nums[i];.
Після завершення циклу повернути max.
Складність: O(n)O(n)O(n) за часом, O(1)O(1)O(1) за додатковою пам'яттю. Для невідсортованого масиву швидше знайти неможливо, оскільки для гарантії результату необхідно оглянути кожен елемент хоча б один раз.
2. Чому майже кожна задача на масив починається з одного проходу циклом?
Інформаційна ентропія: Невідсортований масив не має внутрішньої ієрархічної структури (на відміну від збалансованого дерева чи хеш-таблиці). Шукане значення або властивість може знаходитися в будь-якій комірці з однаковою ймовірністю, тому нижня оцінка складності алгоритму становить Ω(n)\Omega(n)Ω(n).
Збір контексту та метаданих: Одноразовий прохід дозволяє обчислити агреговані показники (суму, екстремуми, частоту символів або префіксний масив), що перетворює подальший пошук на операцію зі складністю O(1)O(1)O(1) або O(log⁡n)O(\log n)O(logn).
Апаратна оптимізація кешу: Послідовний прохід масивом у пам'яті ідеально оптимізований під роботу процесора (CPU Hardware Prefetcher заздалегідь підвантажує наступні кеш-лінії в L1/L2 кеш), що робить один прохід циклом максимально швидкодіючим.
3. Що має робити код, якщо масив порожній?
Захисний бар'єр (Guard Clause): Код повинен безпечно перевіряти вхідні дані на початку методу (if (nums == null || nums.length == 0)), щоб запобігти аварійному викиданню NullPointerException чи ArrayIndexOutOfBoundsException.
Семантика результату залежно від задачі:
Кількісні та адитивні задачі (пошук кількості, суми, довжини підмасиву): повертати нейтральний елемент додавання — число 0 або порожній список/колекцію Collections.emptyList().
Задачі пошуку екстремуму або конкретного елемента (максимум, мінімум, середнє арифметичне): у порожньому масиві максимуму математично не існує. У таких випадках повертають обгортку Optional (наприклад, OptionalInt.empty()) або викидають явний інформативний виняток throw new IllegalArgumentException("Array must not be empty");.
4. Як за один прохід знайти найкращий день купити й найкращий продати акції?
Алгоритм (Best Time to Buy and Sell Stock / варіація алгоритму Кадане):
Зберігаємо мінімальну ціну купівлі, яку зустріли до поточного моменту: minPrice = prices[0], та максимальний прибуток: maxProfit = 0.
Проходимо масивом цін від початку до кінця за один прохід O(n)O(n)O(n):
Якщо поточна ціна менша за minPrice, оновлюємо minPrice = prices[i] (знайшли вигіднішу точку входу).
Інакше рахуємо прибуток при продажу сьогодні: profit = prices[i] - minPrice. Якщо цей прибуток перевищує maxProfit, оновлюємо maxProfit = profit.
Результат: Знаходимо глобальний максимум прибутку за O(n)O(n)O(n) часу без перебору всіх можливих пар днів (O(n2)O(n^2)O(n2)).
5. Тисяча запитів «яка сума чисел з 10-го по 1000-й?» — як відповідати миттєво?
Техніка префіксних сум (Prefix Sums):
За один попередній прохід O(n)O(n)O(n) будується масив префіксних сум prefix розміром n+1n + 1n+1, де кожен елемент prefix[k] зберігає суму перших kkk чисел:
prefix[i]=prefix[i−1]+nums[i−1],де prefix[0]=0\text{prefix}[i] = \text{prefix}[i - 1] + \text{nums}[i - 1], \quad \text{де } \text{prefix}[0] = 0prefix[i]=prefix[i−1]+nums[i−1],де prefix[0]=0
Сума чисел на будь-якому відрізку від індексу LLL до RRR включно обчислюється однією арифметичною дією:
Sum(L,R)=prefix[R+1]−prefix[L]\text{Sum}(L, R) = \text{prefix}[R + 1] - \text{prefix}[L]Sum(L,R)=prefix[R+1]−prefix[L]
Ефективність: Будь-яка кількість запитів (хоч тисяча, хоч мільйон) виконується за O(1)O(1)O(1) часу на запит, не вимагаючи повторного проходження циклом по діапазону.
6. Чи корисно вчити готові прийоми, чи вони заважають думати самому?
Патерни як будівельні блоки мислення: Алгоритмічні прийоми (два вказівники, ковзне вікно, бінарний пошук, префіксні суми, бітові маски) — це базовий інженерний словник. Без знання цих шаблонів розробник змушений щоразу з нуля винаходити базові структури, витрачаючи когнітивний ресурс на тривіальні речі.
Свобода архітектурного мислення: Знання патернів звільняє увагу для аналізу складніших системних задач: вибору коректних інваріантів, обробки граничних умов та проектування масштабованих структур.
Головна умова: Прийоми корисні тоді, коли зрозуміла причина їхньої роботи та їхні обмеження (чому для двох вказівників потрібна монотонність чи сортування, коли префіксні суми непридатні для частих змін масиву). Якщо сприймати патерни як усвідомлений набір інструментів, а не як сліпий шаблон для копіювання, вони значно розвивають аналітичне інженерне мислення.
