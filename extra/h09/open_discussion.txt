1. Навіщо виносити код у функцію, якщо він і так працює?
Повторне використання коду (DRY — Don't Repeat Yourself): Якщо одна й та сама логіка потрібна у трьох різних місцях, дублювання коду призводить до розмноження багів. Виправлення дефекту в єдиній функції автоматично лагодить поведінку всієї системи.
Зниження когнітивного навантаження та самодокументованість: Функція з виразним ім'ям (наприклад, isPalindrome()) приховує деталі реалізації, дозволяючи читати високорівневий бізнес-код як зв'язний текст.
Ізоляція та тестування: Відокремлену функцію можна легко й надійно покрити автоматичними Unit-тестами, перевіривши граничні умови окремо від решти застосунку.
2. Чим параметр відрізняється від аргументу?
Параметр (формальний параметр — Formal Parameter):
Змінна, задекларована у сигнатурі методу при його оголошенні.
Визначає контракт: тип і локальне ім'я даних, які очікує отримати метод (наприклад, у void setAge(int age) змінна age — це параметр).
Аргумент (фактичний аргумент — Actual Argument):
Конкретне значення, константа чи обчислений вираз, що фактично передається у функцію в точці її виклику під час виконання (наприклад, у setAge(25) число 25 — це аргумент).
3. Чому функція «бачить» не всі змінні програми?
Область видимості (Variable Scope): Змінні існують лише в межах того блоку коду ({ ... }), у якому вони були оголошені.
Стековий фрейм виклику (Call Stack Frame): Коли функція викликається, процесор/JVM виділяє для неї окрему ділянку пам'яті на стеку — стековий фрейм. Усі локальні змінні функції розташовані в цьому фреймі. Інша функція має свій ізольований фрейм і фізично не має доступу до локальних адрес чужого стека.
Захист від непередбачених сайд-ефектів (Encapsulation): Якщо кожна функція мала б глобальний доступ до змінних усіх інших частин програми, будь-яка зміна лічильника циклу ламала б виконання паралельних чи викликаних методів.
4. Якої довжини має бути функція?
Принцип єдиного обов'язку (Single Responsibility Principle): Функція повинна виконувати рівно одну логічну дію і робити її якісно.
Практичний орієнтир: У сучасному промисловому коді оптимальною вважається довжина від 5 до 20–25 рядків. Вона має цілком поміщатися на одному екрані монітора без вертикальної прокрутки, щоб розробник міг охопити її логіку поглядом.
Якщо функція перевищує 30–50 рядків, містить глибоку вкладеність умов (if/else) і циклів — це архітектурний сигнал (code smell) про необхідність декомпозиції на кілька менших допоміжних методів.
5. Функція змінила переданий масив, хоча цього не просили. Як так?
Передача за значенням посилання (Pass-by-value of reference):
У Java всі аргументи передаються суворо за значенням (pass-by-value).
Проте для масивів і об'єктів значенням змінної є не сам масив, а адреса посилання на ділянку в оперативній пам'яті (купі/Heap).
Коли ви передаєте масив у метод:
Java
void modify(int[] arr) {
    arr[0] = 999;
}

Параметр arr отримує копію адреси посилання, яка вказує на той самий фізичний масив у купі.
Мутація елемента arr[0] змінює дані безпосередньо за цією адресою, тому оригінальний масив за межами функції виявляється зміненим.
Як запобігти: Якщо функція не повинна модифікувати вхідні дані, вона має створити захисну копію (nums.clone() або Arrays.copyOf()) і працювати з нею.
6. Що функція має повернути, якщо нічого не знайшла?
Залежно від типу результату, семантики мови та контексту задачі застосовують кілька підходів:
Спеціальне значення-індикатор (Sentinel Value):
Для пошуку індексу в масиві повертають -1 (наприклад, класичний indexOf), оскільки дійсні індекси завжди невід'ємні.
Порожній об'єкт або колекція (Null Object Pattern):
Якщо метод шукає набір елементів (список, масив, рядок), повертають порожню колекцію чи порожній рядок (Collections.emptyList(), new int[0], ""), а не null. Це захищає клієнтський код від аварійного падіння з NullPointerException.
Контейнер Optional<T> (найкраща сучасна практика для поодиноких об'єктів):
Замість повернення null метод повертає Optional.empty(). Це змушує того, хто викликає метод, явно обробити випадок відсутності результату (.orElse(), .orElseThrow()).
Викидання винятку (Exception):
Якщо відсутність шуканого значення є критичною аномалією або порушенням контракту системи (наприклад, findUserById() не знайшов запис за обов'язковим первинним ключем), викидають явний інформативний виняток (наприклад, NoSuchElementException чи EntityNotFoundException).
