1. Навіщо в програмуванні окремий тип для «так» і «ні»?
Семантична однозначність: Тип boolean виражає логічний факт (істина або хиба), відділяючи предикати від арифметичних обчислень.
Безпека типів (Type Safety): У мовах на кшталт C, де логічні значення зведені до цілих чисел (0 та не-0), поширеною є помилка заміни оператора порівняння оператором присвоєння (if (x = 0) замість if (x == 0)). Сувора типізація в Java не дозволяє передати числовий вираз в умовний оператор, відсікаючи цілий клас критичних помилок на етапі компіляції.
Оптимізація умовних переходів: Компілятору простіше генерувати оптимізовані інструкції розгалуження процесора (branch prediction), коли тип даних явно гарантує лише два допустимих стани.
2. Як сказати !(a && b) людською мовою?
За першим законом де Моргана логічний вираз (ab) еквівалентний (ab).
Людською мовою це означає:
«Неправда, що виконані обидві умови одночасно».
Або простіше: «Хоча б одне з двох хибне» (не виконано або a, або b, або обидва разом).
3. Чим && відрізняється від &?
&& (Short-circuit conditional AND — коротке замикання): Обчислює операнди ліниво зліва направо. Якщо перший (лівий) операнд повертає false, весь вираз гарантовано є хибним, тому правий операнд процесор взагалі не обчислює.
& (Logical / Bitwise AND — неліниве логічне або побітове І):
Для типів boolean: обчислює обидві частини виразу незалежно від результату першої (жадібне обчислення).
Для цілочисельних типів (int, long): виконує операцію кон'юнкції над кожним бітом двійкового представлення чисел.
4. Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній?
Завдяки механізму короткого замикання оператора &&.
Оскільки x є null, перший предикат x != null повертає false.
Отримавши false на першому кроці, рантайм зупиняє подальший розрахунок усього виразу &&, оскільки результат операції вже визначений.
Доступ до поля x.name ніколи не виконується, завдяки чому критична помилка розіменування нульового вказівника (NullPointerException) не виникає. Якби був використаний оператор &, права частина була б примусово обчислена, і програма впала б з аварійним завершенням.
5. Як запхати 32 відповіді «так/ні» в одне число?
Використовують техніку бітової маски (bitmask) на основі стандартного 32-бітного цілого числа (int), де кожен із 32 розрядів відповідає за один окремий логічний прапорець (номер біта від 0 до 31):
Встановити k-й прапорець у true (встановити 1):
Java
flags |= (1 << k);
Скинути k-й прапорець у false (встановити 0):
Java
flags &= ~(1 << k);
Перевірити стан k-го прапорця:
Java
boolean isSet = (flags & (1 << k)) != 0;
Інвертувати k-й прапорець:
Java
flags ^= (1 << k);
6. Що швидше: n % 2 чи n & 1?
Апаратна різниця: Побітова операція n & 1 вимагає лише одного такту мікропроцесора (інструкція AND), тоді як апаратне цілочисельне ділення/залишок (IDIV) для n % 2 займає від 10 до 40 тактів залежно від архітектури.
Семантична поведінка для від'ємних чисел:
У мовах на кшталт Java оператор % зберігає знак діленого: (-3) % 2 повертає -1. Щоб виконати таку вимогу стандарту, компілятор не може просто замінити n % 2 на звичайний бітовий AND, а мусить додавати додаткові інструкції корекції знаку або умовні зсуви.
Вираз n & 1 дивиться виключно на молодший біт у пам'яті (у доповняльному коді непарне число завжди має одиницю в кінці): (-3) & 1 дає 1.
Висновок: Операція n & 1 швидша, генерує менше машинних інструкцій і прямо відображає перевірку парності на рівні апаратури.
